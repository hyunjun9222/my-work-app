# Weekly Summary

주간 데이터 파일을 읽어 정리 초안을 만든다.

## Input

사용자가 그때그때 지정하는 주간 데이터 파일:

- **이번 회차** 파일 (필수)
- **지난 회차** 파일 (비교용)

파일 경로가 지시에 없으면 진행하기 전에 물어본다. 어느 파일이 이번 회차이고 어느 것이 지난 회차인지 불분명하면 추측하지 말고 확인한다.

## Steps

1. **읽기** — 지정된 데이터 파일을 모두 읽는다. 요약하기 전에 전체를 읽는다.

2. **요약 + 달라진 점** — 이번 회차의 핵심을 **세 줄**로 요약한다. 그 아래에 지난 회차 대비 달라진 점을 **한 줄** 덧붙인다.
   - 세 줄은 세 개의 문장/불릿을 뜻한다. 늘리지 않는다.
   - 달라진 점은 두 회차 데이터를 실제로 비교해서 쓴다. 지난 회차 파일이 없으면 그 줄에 비교 자료가 없다고 적는다.

3. **이슈 목록** — 챙길 이슈를 목록으로 정리한다. 각 항목은 데이터의 어느 부분에서 나온 것인지 알 수 있게 쓴다.

4. **저장** — 결과를 파일 하나로 저장한다.
   - 저장 위치를 사용자가 지정하지 않았으면 작업 폴더의 `outputs/` 에 만든다 (없으면 이번 회차 데이터 파일과 같은 폴더).
   - 파일 이름은 영어로 짓는다 (예: `weekly-summary-2026-07-23.md`). 한글 파일명은 인코딩 문제가 생길 수 있으니 쓰지 않는다.
   - 기존 파일을 덮어쓰게 되는 경우 먼저 사용자에게 확인한다.

## Output

파일 하나. 구성:

```markdown
# 주간 정리 — <기간 또는 회차>

## 요약
- (핵심 1)
- (핵심 2)
- (핵심 3)

## 지난 회차 대비 달라진 점
- (한 줄)

## 챙길 이슈
- (이슈 1)
- (이슈 2)
- ...

---
자료: <읽은 파일 경로들>
```

작업을 마치면 저장한 파일 경로와 요약 세 줄을 사용자에게 알려준다.

## Rules

- **준 자료에 없는 내용은 지어내지 않는다.** 수치, 원인, 배경을 추정해서 채우지 않는다.
- 데이터에 없어서 판단할 수 없는 부분은 비워두지 말고 "자료에 없음"이라고 명시한다.
- 데이터가 서로 모순되거나 빠진 항목이 있으면 임의로 고르지 말고 이슈 목록에 그대로 올린다.
- 원본 데이터 파일은 수정하지 않는다. 읽기만 한다.
